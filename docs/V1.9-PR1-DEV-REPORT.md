## 实现要点

- **日桶×账户×币种聚合**：summariesState.dayBuckets（北京日键→账户→币种→{input,cacheRead,cacheWrite,output,cost,costOffpeak,records,unpriced}），recordUsage 后 O(1) 增量维护；cost 只算 priced 且有限。
- **会话索引**：sessions（账户\0sessionKey，无 sessionId 用 provider/model#ts 兜底键）+ sessionStarts（归一化 sessionId→minTs，跨账户取最小）→ 本会话起点 O(1)，永不随折叠丢失。
- **8 个聚合全部改读桶/索引**：sessionTotals、currentSessionSummary、spendSummary、todaySpend、monthSpend、last30dSpend、totalSpend、providerSpend（O(1)）；getEstimate 合并两次 sessionTotals；getSpendTrend 单次按桶扫描。明细遍历只剩「本会话边界天 + 滚动窗截止日」（二分定位、整天读桶、边界天逐条过滤），与旧两遍全扫逐字段等价。
- **90 天明细折叠**：只删明细、绝不动桶/索引；unpriced 永不折叠；十万条硬顶按整日推进；三步原子化（冷归档 usage-archive/YYYY-MM.jsonl → 原子写 usage-summaries.json（tmp+rename+.bak，失败回滚放弃折叠）→ 才动明细）。summaries 只持久化已折叠部分，与明细重建部分严格不相交——重启精确重建、防双算、防旧版回滚残留。
- **journal 滚动压缩**：快照写成功后按记录 id 剔除已在快照/已折叠区的行（tmp+rename，>2000 行或 >2MB 触发），撕裂行/未知行保守保留。
- **诊断计数** `__usageInternals`（detailScanCalls/detailRecordsScanned/recordUsageCount/foldedRecords/journalCompactions/aggregatesVersion），供测试/运维，不参与业务判定。
- **首次升级**：无 summaries 时启动一次性 O(N) 建桶+索引；首次折叠才重写快照；usage-records.json 保持纯数组格式。

## 相对审计文档的偏差（均经理由论证）

1. journal 压缩用 id 过滤替代字节偏移基线（多实例行序交错下更安全，撕裂行保守保留+id 去重兜底）。
2. 「桶不含边界天」实现为「完整天读桶、边界天读明细」；起点早于 90 天窗的会话边界天退化为整天粒度（天数级误差上限、方向为不丢账）。
3. getSpendTrend 的 byModel 保留一次窗内明细扫描（桶无模型维度；该 RPC 客户端 0 调用）。
4. client-bundle.js 零改动；persistence 落盘失败复用现有 'snapshot-stale' 软提示。
5. lib/ 未提交入库：仓库 .gitignore 明确排除 plugin/lib/（v1.7 起 lib 不入版本控制），已按约定 `npm run build` 同步并由测试验证一致。
6. 病态输入（sessionId 剥离前缀后为空串）由回退无主记录改为返回 null（更安全，现网不可达）。

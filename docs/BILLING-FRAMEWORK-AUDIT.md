# 底部信息栏 · 计费显示体系审计报告

**审计日期**: 2026-08-28
**审计范围**: 三态计费框架（余额制 / 订阅制 / 账单型）全量适配现状对照「适配铁律」的符合度
**触发**: 用户定标准 —— 余额制适配必须 ①官方余额查询 ②价目表覆盖该家全部模型（否则花费恒为 0）
③有分时定价即加峰谷标识；且"先扩框架、填表接模型"，禁止一个模型改一次框架。

## 一、结论速览

> 总体判断：**三态框架骨架是健康的，漏洞不在框架而在"接入完成度"。**
> 框架早已把"余额快照 / 用量记账 / 花费计算 / 峰谷时段"拆成了独立插槽，
> 但历史上接入每家服务商时只做了①余额端点一项，②价目表和③时段配置经常不跟 →
> 表现为"新服务商余额能显示、本会话永远 ¥0"。这正是用户看到的症状。

### 1.2 "为什么会出现这个洞"——根因

1. `PROVIDERS` 表强制了余额适配器，但**没有任何机制强制价目表同步**：接入时漏了也能通过测试。
   → 已加制度性防回归：新增 CI 测试断言"每个带记账可能的 provider 至少有一条价目或显式豁免标记"（本轮落地）。
2. 价目在**记账瞬间冻结**（防止价目表变动篡改历史账单）。收录晚于记录时，历史永远 unpriced。
   → 已实现**一次性回填**：启动时把 unpriced 且现价目表已覆盖的记录按官方价补算（仅动从未有过价格的记录，已 priced 的历史金额绝不重写）。
3. 单一价目源打包在插件里 → 价格滞后=等发版。
   → 已升级为**远程目录自动增量更新**（见第三节）。

## 三、远程价目目录运行规范

- URL（默认）: `https://raw.githubusercontent.com/SONGOAO25/dsh-bottom-info-bar/main/catalog/pricing.json`
  （可用环境变量 `DSH_BOTTOM_INFO_BAR_PRICING_URL` 覆盖，便于私有部署）
- 时序: 启动磁盘缓存同步合并 → 回填 → 异步网络拉取 → 合并成功再回填一次 → 每 6 小时定时
- 校验白名单: key `[A-Za-z0-9._-]{1,64}`；mode 仅 flat；币种仅 CNY/USD；`0 < miss`、`hit ≤ miss`、`out ≥ 0`；条目 ≤512
- 失效策略: 网络/格式异常静默降级（缓存→内置表），不阻塞任何 UI；密钥零参与、匿名请求
- 明确边界: 官方均无"价格查询 API"，新鲜度=目录维护节奏（小时级而非秒级）；此限制已在 README 声明
- 后续增强（P2）: 远程目录扩展**余额端点描述符**（声明式 path/currency 提取规则，有限模板枚举），实现新服务商"零代码接入"

# 运营文档：底部信息栏（dsh-bottom-info-bar）

> 阶段 7 产出 · 基线采集：2026-08-28（v1.9.0 发布同日）

## 关键指标（怎么看 + 基线）

| 指标 | 观测方法 | 基线 | 大白话 |
|---|---|---|---|
| Star | 仓库主页星星数（gh api stargazers_count） | 21 | 公开口碑有多少人认可 |
| 克隆/尝鲜量 | `gh api repos/<repo>/traffic/clones`（14 天窗口） | 900 次/14 天 | 有多少人真的拿来用过 |
| 待处理 Issue | GitHub Issues open（bug/需求模板就在仓库） | 0 | 报障和提需求的队列是否清空 |
| Release 下载 | GitHub Release assets | 0（无二进制资产） | 本插件走 git/本地安装，此指标不适用，以克隆量为准 |
| 真机验收反馈 | 用户的 7 项清单体验 + 评论区留言 + 装机检测插件 | 待用户重启验收 | 最真实的"好用不好用" |

**北极星指标（大白话）**：**"用着不卡、看得明白、有人持续用"**——以「反馈质量 + 评论区互动 + Star 缓步增长」衡量，不追虚量；任何指标异常都要能分开归因（发布/功能/外部环境）。

## 反馈渠道（固定下来）
1. **GitHub Issues**（仓库已配 bug/feature 模板）→ 定期汇入 docs/ROADMAP.md 反馈池
2. **视频评论区**（已产出两条高价值留言的来源）→ 每条留言必回、有采纳价值的进路线图并回帖告知
3. **安装前检测插件**反馈 → 直接进反馈池（v1.9.0 性能隐患即来自此渠道）

## 增长动作（本版选择：暂不宣传，先运营）
- **迭代驱动口碑**：真机验收反馈 → 快速 v1.9.x 修复轮，把"有人认真回复"做成品牌
- **回帖闭环**：对视频下两条留言的用户回复"已采纳并上线 v1.9.0"（设置页 + 性能）
- **每版一个亮点**：v1.9.0 的亮点=「信息底栏」设置页+全关即移除；后续发版沿用同一策略
- 暂不推进：首发宣传物料（用户明确选择暂缓，随时可补做）

## 复盘模板（每周）
- **数据**：Stars / 克隆 / Issues 各变化多少，与上周或发布点对照
- **反馈**：用户说了什么（评论区 / Issues / 装机检测），归类（Bug / 需求 / 体验）
- **行动**：下一轮优先级写回 ROADMAP 反馈池；一个改进项排入下版

## 本轮复盘（2026-08-28）
- 做得好的：性能隐患从反馈到落地一版闭环；用户拍板方向被完整实现（原生/插件分组、全关移除、自定义配色）；QA 抓到隐藏的 CSS 炸弹避免带伤发布
- 要改进的：①子任务执行环境连续故障（QA 两次中断）→ 后续大任务优先拆小批次；②首次打 tag 未先 fetch 导致误标（已修正）→ 发布清单加入「先 fetch 再 reset」检查；③测试对 CSS 只有字符串断言几乎致漏（已补结构断言）→ 后续所有「生成式文本」代码都要求结构级断言

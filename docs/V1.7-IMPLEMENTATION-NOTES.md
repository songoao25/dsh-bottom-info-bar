## 1. FR-8 Codex JWT：实测 claims 形态与调研报告不同（已适配，测试覆盖）

- **调研 A1 记录**：claims 为扁平字段（`chatgpt_plan_type` 在顶层）。
- **本机实测（2026-08-27，`~/.codex/auth.json` id_token）**：订阅字段实际**嵌套在 `https://api.openai.com/auth` 命名空间下**：
  ```json
  {
    "https://api.openai.com/auth": {
      "chatgpt_plan_type": "plus",
      "chatgpt_subscription_active_start": "2026-08-16T08:26:46+00:00",
      "chatgpt_subscription_active_until": "2026-09-16T08:26:46+00:00",
      "chatgpt_subscription_last_checked": "2026-08-23T15:58:53.919722+00:00",
      ...
    }
  }
  ```
- **实现**：`chatgptClaimSource(payload)` 嵌套命名空间优先、扁平兜底（双形态兼容，应对 OpenAI 后续变体）。`parseCodexJwt` 双字段全缺失 → null（静默降级，不报错、不调 wham）。
- **真机验证通过**：真实 auth.json → `planType=plus`、`expiryAt=2026-09-16T08:26:46Z`，信息栏显示 `ChatGPT · Plus | 到期 2026-09-16`。
- **wham 保持默认关闭**：原 `fetchWhamUsage`（chatgpt.com/backend-api/wham/usage，D 级）已从 codex 源移除，本插件对该源**零网络请求**。

## 2. FR-9 小米 MiMo：cn/ams 未真弹（待核实），解析器按 A4 报告容错

- 本机无 `XIAOMI_*` 凭据，三集群均无法真弹验证。
- 解析器按 A4/quota-rs 报告形态容错：`/v1/tokenPlan/usage`（`data.monthUsage` 或 `items[]` 的 `month_total_token`）、`/v1/user/balance`（套餐形态 `token_balance/token_limit/plan_name`；按量形态 `balance/charge_balance/granted_balance`，金额为字符串）。
- **percent 双形态处理**：接口示例 `percent: 0.1661`（0-1 小数）→ 换算 16.61%→17%；若返回 0-100 直接使用（`xiaomiPercentToUsed` 规则：≤1 视为小数 ×100，>1 视为百分比）。
- **月度重置时刻为本地推导**：接口无 reset 字段（A4 记录），实现为「下月 1 日零点」（`nextMonthStartMs`，本地时区），文档注明为推导值。**待核实**：真实响应是否有 `resetsAt` 类字段，若有应改用接口值。
- 主端点失败（404/形态不符）→ 自动回退 `/v1/user/balance` 套餐形态。

## 3. FR-10 Together：任务书主端点与调研报告域名不同（双 host 回退）

- 任务书指定 `https://api.together.xyz/billing/usage`；A8 调研记录 `https://api.together.ai/billing/usage`。二者均为官方域名（SDK 用 api.together.xyz，docs.together.ai 链接 api.together.ai）。

## 4. FR-11 Fireworks：端点回退链实现 + 真实响应待核实

- 按任务书/A8：先 `GET /v1/accounts` 解析 account_id（兼容 `accounts[]` / 裸数组 / `data[]` / `id` 字段）；再用 `GET /v1/accounts/{id}/billing/summary?granularity=DAILY`（lineItems[].totalCost 求和，回退 usageBuckets[].cost 求和）→ 账单金额。
- **404 回退**：summary 404 时尝试 `GET /v1/accounts/{id}/billingUsage`（token 用量）；无金额时客户端显示 `本月用量 N tokens` 并注明数据源。A8 还列出 `POST /usageCosts:query`（管理员作用域），**未采用**（避免 POST + 额外作用域）。
- 真实响应形态待有密钥时核实（A8 标 🟢 官方）。

## 5. FR-12 AWS Bedrock：SigV4 实现与测试向量

- **SigV4 用 node:crypto 纯实现**（`awsSigV4Headers`），单测采用 **AWS 官方 Signature V4 测试向量（IAM ListUsers 例）**：
  - 期望签名 `5d672d79c15b13162d9279b0855cfba6789a8edb4c82c400e06b5924a6f2b5d7`（与官方文档一致，测试全绿）。
- Cost Explorer：`POST https://ce.us-east-1.amazonaws.com/`，`X-Amz-Target: AWSInsightsIndexService.GetCostAndUsage`，TimePeriod=本月（Start=本月 1 日，End=明日，枚举）→ `ResultsByTime[0].Total.UnblendedCost.Amount`。
- 预算%：**先 STS GetCallerIdentity 取 AccountId，再 `budgets.amazonaws.com` GetBudgets**（`X-Amz-Target: AWSBudgetServiceGateway.GetBudgets`）→ 首笔预算 `CalculatedSpend.ActualSpend / BudgetLimit.Amount × 100`；任何一步失败 → 静默 null（客户端只显示 `本月 $X`）。
- 凭据：仅支持 `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY`（可选 `AWS_SESSION_TOKEN`）——**AWS_PROFILE / IRSA / ECS 角色等未接入（待核实清单）**；无凭据 → 「未配置」引导。
- CE/Budgets 固定用 us-east-1 签名（全局服务端点）。悬挂备注：账单延迟约 24h（hover 注明）。
- **注意**：payload 哈希始终参与 canonical request，但不发送 `x-amz-content-sha256` 头（与官方测试向量一致；AWS 服务端按请求体自算校验）。

## 6. FR-13 Cloudflare：paygo 端点真实响应未实测（待核实），免费额度「别编」规则

- 端点：`GET https://api.cloudflare.com/client/v4/accounts/{account_id}/billing/usage/paygo`（Alpha），凭据 `CLOUDFLARE_API_KEY`（Bearer）+ `CLOUDFLARE_ACCOUNT_ID`。
- 解析按 A9 示例形态容错：`result[]` 逐项求和 `cost`（→ 本月花费）/ `usage`（→ 本月用量）。
- **免费额度规则（重要）**：仅当响应条目**显式包含数字型 `limit`/`allowance`（上限）与 `used`/`usage`（已用）**时才推导剩余额度与「距重置」；重置时刻 = 下一个 UTC 零点（本地推导，Cloudflare 免费额度按 UTC 日重置）。接口给不出免费额度时**只显示真实用量/花费，绝不编造**。
- 无真实凭据，实际响应字段待核实（A9 标 Alpha/B 级）。
